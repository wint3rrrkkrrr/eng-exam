# ภารกิจ: เพิ่มเกมแววูฟ (Werewolf) เข้าไปใน web app เดิม (repo: wint3rrrkkrrr/eng-exam)

## 0. บริบท
- โปรเจกต์นี้เป็นเว็บเก่าของผู้ใช้ ใช้ React 19 + Vite 6 + TypeScript + Tailwind 4 + motion + lucide-react, มี server.ts (Express), ใช้ Supabase (@supabase/supabase-js), มีไฟล์ supabase_setup.sql และ supabase_cheese_game_setup.sql (มีเกมอยู่แล้วอย่างน้อยหนึ่งเกม), deploy ผ่าน Netlify (netlify.toml)
- งานนี้: เพิ่ม "เกมแววูฟ" เป็นเกมใหม่ในเว็บเดียวกัน ไม่เกี่ยวกับโปรเจกต์อื่น
- ผู้ใช้ไม่ถนัดการเขียนโค้ด: อธิบายเป็นภาษาไทยง่ายๆ, ทุกครั้งที่จบขั้นตอนให้บอกวิธีรันและวิธีทดสอบเป็นข้อๆ, อธิบายศัพท์เทคนิคทุกครั้งที่ใช้
- ข้อความทุกอย่างในเกมเป็นภาษาไทย (ชื่อตัวแปร/โค้ดเป็นอังกฤษได้)

## 1. ขั้นตอนแรก (ห้ามข้าม): ตรวจของเก่าก่อน
1. อ่านโค้ดทั้งโปรเจกต์ แล้วเขียน REUSE_AUDIT.md สรุป:
   - โครงสร้างโฟลเดอร์, วิธีที่หน้าเว็บสลับระหว่างเกม/หน้า (routing หรือ state)
   - ระบบห้อง/ล็อบบี้/ผู้เล่นหลายคน และ "ระบบเรียลไทม์" ที่ใช้อยู่ (Supabase Realtime? polling? อย่างอื่น?)
   - ระบบตัวตนผู้เล่น (ชื่อเล่น, ล็อกอิน, session)
   - schema ฐานข้อมูลปัจจุบัน และ RLS policy ของเกมเดิม (ดูจาก SQL ที่มี)
   - หน้าที่ของ server.ts (มี API อะไรบ้าง) และวิธี deploy จริงบน Netlify (Express รันบน Netlify ได้ไหม หรือใช้ Functions/ส่วนอื่น)
   - UI กลาง: ปุ่ม, โมดัล, ธีมสี, ฟอนต์, แอนิเมชัน, คอมโพเนนต์ที่ใช้ซ้ําได้
2. แบ่งเป็น (ก) ใช้ต่อได้เลย (ข) ใช้ได้แต่ต้องดึงออกมาเป็นส่วนกลาง (ค) ต้องทําใหม่ พร้อมเหตุผลสั้นๆ
3. กฎเหล็ก: ของเก่าใช้ได้ให้ใช้ของเก่า ห้ามเขียนใหม่โดยไม่จําเป็น ห้ามทําให้เกมเดิมพัง ทําเกมใหม่เป็นโมดูล/โฟลเดอร์แยก (เช่น src/games/werewolf) และใช้ตาราง Supabase ใหม่ที่ขึ้นต้นด้วย ww_ แยกจากเกมเดิม
4. ก่อนเขียนโค้ด ให้รายงานผล audit แล้วถามผู้ใช้ไม่เกิน 5 ข้อที่ตอบง่าย (เช่น เล่นออนไลน์คนละเครื่อง หรือเล่นผ่านเครื่องเดียว, จํานวนผู้เล่นปกติ, ใช้ธีมหน้าตาเดียวกับเกมเก่าไหม) แล้วรอคําตอบ

## 2. หลักการ: กติกาต้องตรงกับเกมจริง
- อ้างอิงกติกามาตรฐานของ "Werewolves of Millers Hollow" (บทแม่แบบ) และ "Ultimate Werewolf" (บทเสริมและระบบสมดุล) ทําเป็น "พรีเซ็ตกติกา" ให้เลือก
- จุดที่แต่ละฉบับต่างกัน ห้ามเดา ให้ทําเป็นตัวเลือกตั้งค่า มีค่าเริ่มต้นตามฉบับมาตรฐาน พร้อมคําอธิบายไทยใต้ทุกตัวเลือก
- ข้อไหนไม่แน่ใจ ให้จดใน OPEN_QUESTIONS.md แล้วถามผู้ใช้ ไม่ใช่เดาแล้วทําต่อ
- แยก "เครื่องยนต์กติกา" (rules engine เป็น TypeScript ล้วน ไม่มี UI ไม่ยุ่งกับฐานข้อมูล) ออกจากหน้าตาและระบบเครือข่าย เพื่อเขียนเทสต์ได้
- ความลับต้องปลอดภัยจริง: ฝั่งเซิร์ฟเวอร์เป็นผู้ตัดสินและเก็บบทบาท, เครื่องผู้เล่นแต่ละคนได้รับเฉพาะข้อมูลที่ตัวเองควรเห็น (หมาป่าเห็นหมาป่าด้วยกัน คู่รักเห็นกัน ฯลฯ) ห้ามส่งบทของคนอื่นมาที่เบราว์เซอร์ และตั้ง RLS ใน Supabase ให้ผู้เล่นอ่านบทของคนอื่นไม่ได้ ห้ามใช้ service role key ในโค้ดฝั่งเบราว์เซอร์
- ถ้า Netlify รัน Express ต่อเนื่องไม่ได้ ให้เสนอทางเลือกที่ทํางานได้จริง (เช่น Netlify Functions หรือ Supabase Edge Functions) พร้อมข้อดีข้อเสียก่อนตัดสินใจ

## 3. โครงเกม
### 3.1 ก่อนเริ่ม
- ห้อง: รหัสห้อง/ลิงก์เชิญ, ผู้เล่น 5-30 คน (ตั้งค่าได้), เจ้าของห้อง, ชื่อเล่น/อวตาร์
- เจ้าของห้องเลือกพรีเซ็ตหรือกําหนดบทเอง, ระบบตรวจว่าจํานวนบทเท่ากับจํานวนผู้เล่น, มีตัวช่วยแนะนําสัดส่วนหมาป่าและตัวบอกความสมดุล (คะแนนบทแบบ Ultimate Werewolf)
- สุ่มแจกบทแบบลับ
### 3.2 กลางคืน (ผู้ดําเนินเกมอัตโนมัติเรียกทีละบท)
ลําดับตื่นมาตรฐาน (ข้ามบทที่ไม่มีในเกม):
1. ขโมย (คืนแรก) 2. กามเทพ (คืนแรก) แล้วคู่รักตื่นมาดูหน้ากัน 3. เด็กป่า (คืนแรก) 4. ผู้พิทักษ์/หมอ 5. ผู้หยั่งรู้ 6. หมาป่า 7. หมาป่าตัวใหญ่ (เหยื่อรายที่สองตามเงื่อนไข) 8. แม่มด 9. บทอื่นที่มีพลังกลางคืน
- กันการเดาจากเวลา: ทุกบทที่ถึงตา (รวมบทที่ตายแล้วหรือไม่มีในเกม) ให้ใช้เวลารอใกล้เคียงกันแบบสุ่มช่วงสั้นๆ
- ลําดับการตัดสินผลตอนเช้า ต้องกําหนดชัดและเขียนเทสต์: การกัดของหมาป่า → การป้องกัน → ยาชุบชีวิต → ยาพิษ → คู่รักตายตาม → นายพรานยิง (ต่อเนื่องเป็นลูกโซ่จนหมด) → ส่งต่อตําแหน่งหัวหน้าหมู่บ้าน
### 3.3 กลางวัน
1. ประกาศผู้เสียชีวิต (เปิดเผยบทตามตัวเลือกตั้งค่า)
2. เหตุการณ์ต่อเนื่อง (นายพราน, คู่รัก, ส่งต่อตําแหน่ง)
3. หลังคืนแรก: เลือกตั้งหัวหน้าหมู่บ้าน (ถ้าเปิด)
4. อภิปราย (แชทข้อความ พร้อมตัวจับเวลา และตัวเลือกปิดแชทถ้าเล่นคุยกันจริง)
5. โหวตประหาร
6. ประกาศผล แล้วตรวจเงื่อนไขชนะ ก่อนเข้าคืนถัดไป
- ตรวจเงื่อนไขชนะ "ทุกครั้งที่มีคนตาย" ไม่ใช่เฉพาะท้ายรอบ
### 3.4 เงื่อนไขชนะ
- ชาวบ้านชนะ: หมาป่าทุกตัวตาย
- หมาป่าชนะ: หมาป่าที่รอด >= ผู้เล่นฝ่ายอื่นที่รอด (ตั้งค่าเกณฑ์ได้)
- คู่รักข้ามฝ่ายชนะ: เหลือรอดสองคนนั้นเท่านั้น (เปิด/ปิดได้)
- ฝ่ายที่สาม (คนบ้า, ฆาตกรต่อเนื่อง) ชนะตามเงื่อนไขของบทนั้น
- หน้าสรุปจบเกม: เปิดบทของทุกคน + ไทม์ไลน์เหตุการณ์ทั้งเกม

## 4. บทบาท (เก็บเป็น "ข้อมูลบทบาท" เพิ่มบทใหม่ได้ง่ายโดยไม่ต้องแก้เครื่องยนต์)
### แพ็กหลัก (ทําก่อน)
- ชาวบ้าน
- มนุษย์หมาป่า: เลือกเหยื่อร่วมกัน (ถ้าเห็นไม่ตรงกัน ตั้งค่าได้: ไม่มีใครตาย / สุ่ม / หัวหน้าฝูงตัดสิน)
- ผู้หยั่งรู้: คืนละครั้ง ดูบทผู้เล่นหนึ่งคน (ตั้งค่า: เห็นบทจริง หรือเห็นแค่ฝ่าย)
- หมอ/ผู้พิทักษ์: ป้องกันหนึ่งคนจากหมาป่า (ตั้งค่า: ป้องกันตัวเองได้ไหม, ป้องกันคนเดิมซ้ําสองคืนติดได้ไหม)
- แม่มด: ยาชุบชีวิต 1 + ยาพิษ 1 ใช้อย่างละครั้งทั้งเกม (ตั้งค่า: ใช้สองขวดในคืนเดียวได้ไหม, ช่วยตัวเองได้ไหม)
- นายพราน: เมื่อตาย ต้องยิงหนึ่งคนทันที (ตั้งค่า: รวมกรณีถูกพิษ/ตายตามคู่รักไหม)
- กามเทพ: คืนแรกเลือกคู่รัก 2 คน (เลือกตัวเองได้ไหมตั้งค่าได้) คนหนึ่งตาย อีกคนตายตาม
- เด็กหญิงตัวน้อย: แอบดูตอนหมาป่าตื่น (ตั้งค่า: โอกาสถูกจับได้และผลที่ตามมา)
- หัวหน้าหมู่บ้าน (ตําแหน่ง ซ้อนกับบทอื่นได้): โหวตนับสองเท่า, ตัดสินเมื่อคะแนนเสมอ (ตั้งค่า), เมื่อตายต้องเลือกผู้สืบทอด
- คนโง่ประจําหมู่บ้าน: ถ้าถูกโหวตประหารจะรอดแต่เสียสิทธิ์โหวต
### แพ็กเสริม (ทําหลังแพ็กหลักผ่านเทสต์)
ลูกหมาป่า, หมาป่าตัวใหญ่, หมาป่าหัวหน้าฝูง, สมุนหมาป่า, เด็กป่า, ขโมย, ผู้ถูกสาป, เมสัน, คนบ้า (ชนะถ้าถูกประหาร), ร่างทรง, ฆาตกรต่อเนื่อง
- ทุกบทต้องมีใน RULES.md: ชื่อไทย, ฝ่าย, คําอธิบายสั้น, เวลาที่ตื่น, ข้อจํากัด, ปฏิสัมพันธ์กับบทอื่น (เช่น ผู้หยั่งรู้ดูสมุนหมาป่าเห็นเป็นอะไร)

## 5. ระบบตั้งค่า (ตั้งค่าได้ละเอียด จัดหมวดในหน้าตั้งค่าของเจ้าของห้อง มีปุ่ม "ค่ามาตรฐาน" และบันทึก/โหลดพรีเซ็ตของตัวเอง)
- ทั่วไป: จํานวนผู้เล่น, พรีเซ็ตกติกา, ภาษา/คําศัพท์ที่ใช้เรียกบท
- บทบาท: เปิด/ปิดแต่ละบท, จํานวนของแต่ละบท, ตัวช่วยสมดุล
- เวลา: เวลาอภิปราย, เวลาโหวต, เวลาแอคชันตอนกลางคืน, เวลาเพิ่มเมื่อมีคนขอ, หมดเวลาแล้วทําอะไร (ข้าม/สุ่ม)
- การเปิดเผย: เปิดบทเมื่อตายไหม (บทเต็ม/ฝ่ายเดียว/ไม่เปิด), เปิดจํานวนหมาป่าที่เหลือไหม
- การโหวต: โหวตลับ/เปิดเผย, ข้ามโหวตได้ไหม, ต้องเสียงข้างมากเด็ดขาดหรือแค่สูงสุด, คะแนนเสมอทําอย่างไร (ไม่มีใครตาย / โหวตใหม่แล้วไม่มีใครตาย / สุ่ม / หัวหน้าตัดสิน)
- คืนแรก: มีการฆ่าคืนแรกไหม, ผู้หยั่งรู้ได้ดูคืนแรกไหม
- ผู้ตาย: แชทผู้ตาย, ดูข้อมูลทุกอย่างได้ไหม (โหมดผู้ชม)
- ห้อง: รหัสผ่านห้อง, ให้ผู้ชมเข้าได้ไหม, เตะผู้เล่น, ผู้เล่นหลุดแล้วกลับเข้ามาได้ไหม
- ผู้เล่นหลุดกลางเกม: รอ/ให้บอทเล่นแทน/ถือว่าตาย (ตั้งค่า)

## 6. ระบบอื่นๆ ที่ต้องมี
- ผู้ดําเนินเกมอัตโนมัติ (บรรยายเป็นข้อความไทยทุกเฟส ตัวอย่าง "หมู่บ้านหลับใหล ผู้หยั่งรู้ตื่นขึ้น") พร้อมแอนิเมชันเปลี่ยนกลางวัน/กลางคืนด้วย motion
- แชท: แชทสาธารณะ, แชทหมาป่า (กลางคืน), แชทคู่รัก, แชทผู้ตาย
- บันทึกเกม (game log) เก็บทุกเหตุการณ์ ใช้ทําหน้าสรุปจบเกมและทบทวนย้อนหลัง
- โหมดทดสอบด้วยบอท: บอทสุ่มเล่นได้ทุกบท เอาไว้ทดสอบทั้งเกมคนเดียว
- รองรับมือถือเป็นหลัก (ผู้ใช้เล่นกับเพื่อนผ่านมือถือ), ปุ่มใหญ่ อ่านง่าย
- หน้า "วิธีเล่น/กติกา" ในเกม อธิบายทุกบทและกติกาเป็นภาษาไทย
- เสียง/แอนิเมชันเสริม ทําเป็นลําดับท้ายสุด

## 7. กรณีขอบที่ต้องเขียนเทสต์ (อย่างน้อย)
- หมอป้องกันคนที่ถูกกัด + แม่มดชุบซ้ํา (ผลต้องตรงกติกา ไม่ซ้อนกันแบบผิดๆ)
- คนที่ถูกกัดเป็นคู่รัก, คู่รักตายพร้อมกันจากสองสาเหตุ
- นายพรานตายจากการโหวต / จากพิษ / จากคู่รักตายตาม แล้วยิงคู่รักของใครต่อเป็นลูกโซ่
- นายพรานยิงคนที่เป็นหัวหน้าหมู่บ้าน → ส่งต่อตําแหน่ง
- หัวหน้าหมู่บ้านถูกกัดและตาย, หัวหน้าหมู่บ้านเป็นบทอื่นพร้อมกัน
- คะแนนโหวตเสมอทุกรูปแบบ
- คนโง่ถูกโหวตแล้วโหวตครั้งถัดไป
- ผู้เล่นหลุดกลางเฟสกลางคืน
- เงื่อนไขชนะพร้อมกันหลายฝ่ายในเหตุการณ์เดียว (กําหนดลําดับความสําคัญและจด RULES.md)
- ตรวจว่าผู้เล่นปลอมคําขอ (เช่น ส่งแอคชันของบทที่ตัวเองไม่ได้ถือ, ส่งซ้ํา, ส่งผิดเฟส) ถูกเซิร์ฟเวอร์ปฏิเสธ

## 8. เอกสารที่ต้องสร้างและอัปเดตตลอด
- REUSE_AUDIT.md (ข้อ 1), RULES.md (กติกาและบททุกตัวพร้อมตัวเลือกตั้งค่า), GAME_SPEC.md (สถาปัตยกรรม, โครงข้อมูล, ลําดับเฟส, ข้อความจากเซิร์ฟเวอร์ถึงผู้เล่น), OPEN_QUESTIONS.md, PLAN.md (แผนงานและสถานะ)

## 9. แผนงาน (ทําทีละ milestone จบแล้วหยุดให้ผู้ใช้ทดสอบ ก่อนไปต่อ ทุก milestone commit แยก)
M0 ตรวจของเก่า: REUSE_AUDIT.md + คําถามถึงผู้ใช้ → ผ่านเมื่อผู้ใช้ตอบคําถามแล้ว
M1 เขียน RULES.md + GAME_SPEC.md + schema Supabase (ww_*) + RLS → ผ่านเมื่อผู้ใช้อ่านกติกาแล้วตอบ OPEN_QUESTIONS
M2 เครื่องยนต์กติกา (แพ็กหลัก) + เทสต์ครบตามข้อ 7 → ผ่านเมื่อเทสต์ทั้งหมดผ่าน, จําลองเกมครบวงจรด้วยบอทในเทอร์มินัลได้
M3 ห้อง/ล็อบบี้/ตั้งค่า + เรียลไทม์ + ส่งข้อมูลแบบกรองความลับ → ผ่านเมื่อเปิดสองแท็บ/สองเครื่องเข้าห้องเดียวกันได้และผู้เล่นมองไม่เห็นบทของอีกฝ่าย
M4 หน้าจอเล่นจริง: กลางคืน/กลางวัน/โหวต/แชท/จบเกม + UI มือถือ → ผ่านเมื่อเล่นจบเกมได้ 1 เกมโดยบอท + คนจริง
M5 ระบบตั้งค่าครบทุกหมวด + ผู้เล่นหลุด/กลับเข้าห้อง + โหมดผู้ชม → ผ่านเมื่อตัวเลือกแต่ละตัวมีผลตรงตามคําอธิบายและมีเทสต์
M6 แพ็กเสริมทีละบท (ทําทีละ 1-2 บท พร้อมเทสต์ ไม่ทําพร้อมกันทั้งหมด)
M7 เก็บงาน: หน้าวิธีเล่น, แอนิเมชัน/เสียง, ตรวจ deploy บน Netlify, ทดสอบความปลอดภัย (ลองโกงเองดู), เขียนวิธีใช้งานสําหรับผู้ใช้

## 10. วิธีทํางาน
- ก่อนเริ่มแต่ละ milestone บอกแผนสั้นๆ ว่าจะแก้ไฟล์ไหน แล้วค่อยลงมือ
- ห้ามแตะ/ลบ/เปลี่ยนพฤติกรรมของเกมเดิมโดยไม่แจ้ง ถ้าจําเป็นต้องแก้ไฟล์ส่วนกลาง ให้บอกเหตุผลและตรวจว่าเกมเดิมยังทํางาน
- ไม่ใส่คีย์ลับ (Supabase service key, API key) ลงในโค้ดฝั่งเบราว์เซอร์หรือ commit ลง repo ให้ใช้ .env และอัปเดต .env.example
- ถ้าเจอบั๊กหรือกติกากํากวม หยุดแล้วถามผู้ใช้ อย่าเงียบๆ ตัดสินใจเอง
- จบทุก milestone ให้สรุป: ทําอะไรเสร็จ, ทดสอบอย่างไร, ข้อจํากัดที่เหลือ, สิ่งที่ผู้ใช้ต้องทําเอง (เช่น รัน SQL ใน Supabase)
