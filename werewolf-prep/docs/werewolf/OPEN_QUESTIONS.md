## ส่วน ข — การตัดสินใจทางเทคนิค (มีข้อเสนออยู่แล้ว ขอแค่ยืนยัน)

### 🟢 Q6 — ลิงก์เชิญเข้าห้อง
เว็บนี้ไม่มีระบบ URL แยกต่อหน้า (ไม่มี router) ถ้าอยากส่งลิงก์ให้เพื่อนกดเข้าห้องได้เลย ต้องเพิ่มการอ่าน `?ww=รหัสห้อง` ตอนเปิดเว็บ
- **ข้อเสนอ:** ทำ เพราะเป็นงานเล็ก (~20 บรรทัด) และเล่นกับเพื่อนสะดวกขึ้นเยอะ · ไม่ต้องลง react-router
- **ทางเลือก:** ไม่ทำ ให้พิมพ์รหัส 5 ตัวเอง (เหมือนเกมหนูชีส)
- **คำตอบ:** ไม่ทำ — พิมพ์รหัสห้อง 5 ตัวเอง

### 🟢 Q7 — วิธีกันความลับ (สำคัญที่สุดในส่วนนี้)
เว็บนี้ไม่มีระบบล็อกอิน ทุกคนเป็น `anon` เหมือนกันหมด → RLS แยกคนไม่ออก (เหตุผลเต็มใน `REUSE_AUDIT.md` ข้อ 4)
- **ข้อเสนอ (A):** ปิดตารางความลับไม่ให้ `anon` อ่านเลย + ให้ข้อมูลส่วนตัวไหลผ่าน Netlify Function ที่ตรวจ "ตั๋วผู้เล่น"
  → ปลอดภัยแน่นอน ไม่ต้องรื้อระบบชื่อเล่นเดิม
- **ทางเลือก (B):** เปิด Supabase Anonymous Sign-in ให้ทุกคนมี uid จริง แล้วใช้ RLS คุมตรงๆ
  → สวยกว่าในทางทฤษฎี แต่ต้องตั้งค่า Auth ใหม่ และผู้เล่นเปลี่ยนเครื่องแล้วหลุด
- **คำตอบ:** ทาง A — ปิดตารางความลับ + ตั๋วผู้เล่น + Netlify Function

### 🟢 Q8 — ที่อยู่ของ "เซิร์ฟเวอร์ตัดสิน"
`server.ts` ที่มีอยู่ **ไม่ได้ทำงานบนเว็บจริง** (Netlify ปล่อยแค่ไฟล์ static) จึงต้องสร้างใหม่
- **ข้อเสนอ:** **Netlify Functions** — อยู่ที่เดิม ไม่เพิ่มผู้ให้บริการ ไม่มีค่าใช้จ่ายเพิ่มในแพลนฟรี deploy พร้อม build เดิม
- **ทางเลือก:** Supabase Edge Functions (ต้องลง CLI + เรียน Deno) · ย้าย Express ไป Render/Fly (เพิ่มบริการ + เครื่องฟรีมักหลับทำให้เกมค้าง)
- **สิ่งที่คุณต้องทำเองถ้าเลือก Netlify Functions:** ไปตั้งค่า env 2 ตัวบน Netlify → `SUPABASE_URL` และ `SUPABASE_SERVICE_ROLE_KEY` (Claude จะบอกขั้นตอนเป็นข้อๆ ตอนถึง M3)
- **คำตอบ:** ฐานข้อมูล = Supabase โปรเจกต์เดียวกับเกมหนูชีส (ผู้ใช้ยืนยัน) · เซิร์ฟเวอร์ตัดสิน = **Netlify Functions** (ผู้ใช้ให้ Claude เลือก: ไม่ต้องลง CLI ไม่เพิ่มผู้ให้บริการ · เวลาหมดเฟสเก็บใน DB แล้วให้ไคลเอนต์เรียก `tick` เพราะ Function รันตัวจับเวลาค้างไม่ได้)

## ส่วน ค — กติกาที่ MH/UW ไม่ได้ระบุชัด (ต้องตัดสินใจเอง)

### 🟢 Q9 — หลายฝ่ายชนะพร้อมกันในเหตุการณ์เดียว
เช่น เหลือหมาป่า 1 + ชาวบ้าน 1 ที่เป็น **คู่รักกัน** → ทั้ง "หมาป่าชนะ" และ "คู่รักชนะ" เป็นจริงพร้อมกัน
- **ข้อเสนอ:** คู่รัก > ฝ่ายที่สามรายบุคคล > หมาป่า > ชาวบ้าน (เงื่อนไขที่แคบกว่าชนะ) — เขียนไว้แล้วใน `RULES.md` 7.2
- **คำตอบ:** เงื่อนไขแคบกว่าชนะ: คู่รัก > ฝ่ายอิสระรายบุคคล > หมาป่า > ชาวบ้าน

### 🟢 Q10 — เด็กหญิงตัวน้อย "แอบดู" ในเกมออนไลน์
บนโต๊ะคือการแอบลืมตาจริงๆ ซึ่งแปลงมาเป็นหน้าจอตรงๆ ไม่ได้
- **ข้อเสนอ:** ให้ปุ่ม "แอบดู" กดค้าง กดค้างยิ่งนานยิ่งเห็นชัดขึ้นแต่โอกาสถูกจับสูงขึ้น (เริ่มต้น 25% ต่อการแอบดู 1 ครั้ง)
- **ทางเลือก:** ปิดบทนี้ไปเลยในแพ็กหลัก แล้วค่อยทำที่ M6
- **คำตอบ:** ไม่ทำ — ตาม 50 บทของผู้ใช้

### 🟢 Q11 — ตัวเลขคะแนนสมดุล
คะแนนบทใน `RULES.md` ข้อ 11.2 เป็นตัวเลขที่ **ตั้งขึ้นให้ใช้งานได้** ไม่ใช่ตัวเลขทางการจากหนังสือ Ultimate Werewolf
- **ข้อเสนอ:** ใช้ชุดนี้ไปก่อน เก็บไว้ในไฟล์ข้อมูลบท แก้ง่าย แล้วปรับจากการเล่นจริง
- **คำตอบ:** ใช้ตัวเลขที่ตั้งไว้ไปก่อน แล้วปรับจากการเล่นจริง

### 🟢 Q12 — ผู้เล่นเปลี่ยนเครื่อง/ล้างข้อมูลกลางเกม
ตั๋วผู้เล่นหายแล้วกลับเข้าห้องไม่ได้ จะเอาที่นั่งคืนอย่างไร
- **ข้อเสนอ:** เจ้าของห้องมีปุ่ม "ปล่อยที่นั่งคืน" (ออกตั๋วใหม่ให้ที่นั่งนั้น) — มีความเสี่ยงให้เจ้าของห้องโกงได้ แต่เล่นกับเพื่อนถือว่ายอมรับได้
- **ทางเลือก:** ไม่ให้กลับเข้ามาเลย ถือว่าตาย
- **คำตอบ:** เจ้าของห้องกด "ปล่อยที่นั่งคืน"

### 🟢 Q13 — คนบ้าถูกประหารแล้วเกมจบทันทีไหม
- **ข้อเสนอ:** จบทันที (คนบ้าชนะ) เพราะเข้าใจง่ายที่สุด · ตั้งค่าได้ว่าให้เกมเดินต่อ
- **คำตอบ:** จบทันที (คนฟอกชนะ แล้วเกมจบ)

### 🟢 Q14 — ภาษาและคำเรียกบท
โจทย์บอก "ภาษา/คำศัพท์ที่ใช้เรียกบท" ตั้งค่าได้
- **ข้อเสนอ:** ทำภาษาไทยอย่างเดียวก่อน (เอกสารนี้ใช้ชื่อไทยทั้งหมด) แต่เก็บข้อความไว้ไฟล์เดียว (`text/th.ts`) เผื่อเพิ่มอังกฤษภายหลัง
- **คำตอบ:** ไทยอย่างเดียวก่อน เก็บข้อความไว้ `text/th.ts`

### 🟢 Q17 — ชื่อบทที่ซ้ำ/ต่างกัน
- **คนฟอก (Tanner)** = **คนบ้า** ใน RULES.md ใช่ไหม? และ **ตัวตลก (Jester)**, **คนโง่เจ้าเล่ห์ (Fool)** ก็มีเงื่อนไขชนะ "ถูกโหวตออก" เหมือนกัน → มี 3 บทที่ทำงานเหมือนกัน
  - **ข้อเสนอ:** ทำเป็นบทเดียวที่ต่างกันแค่ผลหลังชนะ (ฟอก = ชนะแล้วจบเกม / ตัวตลก = เลือกผู้โหวต 1 คนให้รับผล / คนโง่เจ้าเล่ห์ = ไม่ชนะถ้าถูกหมาป่าฆ่า) หรือจะตัดเหลือ 1–2 บท
- **ผู้ใหญ่บ้าน (Mayor)** = **หัวหน้าหมู่บ้าน** ใช่ไหม? ใน RULES.md เป็น "ตำแหน่ง" ที่เลือกตั้ง ส่วนเอกสารใหม่เป็น "บท" ที่ได้มาตอนแจกบท
- **ช่างก่อสร้าง** = **เมสัน**, **ผู้คุ้มกัน (Bodyguard)** ≈ **ผู้พิทักษ์/หมอ** — ใน 50 บท **ไม่มี "หมอ"** แต่ข้อ 2, 19, 20 อ้างถึงหมอ → หมอ (ป้องกัน) กับผู้คุ้มกัน (อาจตายแทน) เป็นคนละบทหรือบทเดียว?
- **คำตอบ:** ใช้ข้อเสนอทั้งชุด: ฟอก=ถูกโหวตชนะ+เกมจบ · ตัวตลก=ชนะ+เลือกผู้โหวต 1 คนตายตาม+เกมจบ · คนโง่เจ้าเล่ห์=ชนะเฉพาะตัวถ้าถูกโหวต เกมไม่จบ ไม่ชนะถ้าหมาป่าฆ่า · เพิ่ม "หมอ" (กันได้ 1 คน/คืน กันตัวเองได้ คนเดิมซ้ำไม่ได้ กันเฉพาะการโจมตี) แยกจากผู้คุ้มกัน (ถ้าผู้ถูกคุ้มกันโดนโจมตี ผู้คุ้มกันตายแทน) · ผู้ใหญ่บ้าน=บทที่ได้ตอนแจกบท ไม่ใช่ตำแหน่งเลือกตั้ง

### 🟢 Q19 — "ฝ่าย" ที่ไม่ใช่ 3 กลุ่ม
ข้อ 1 บอกมี 3 กลุ่ม (ชาวบ้าน/หมาป่า/อิสระ) แต่ในบทมีฝ่ายอื่น: **แวมไพร์** (ฝ่ายของตัวเอง) · **ลัทธิ** · **พิเศษ** (ผู้ลอกเลียนแบบ, หญิงชรา, มนุษย์ป่า, ผู้หยุดความสามารถ, ผู้สลับชะตา, ผู้ควบคุมเวลา) · **"มนุษย์หมาป่าพิเศษ"** (หมาป่าเดียวดาย)
- ฝ่าย "พิเศษ" **ไม่มีเงื่อนไขชนะ** ในเอกสาร → ต้องกำหนดรายบท

- **คำตอบ:** ผู้ใช้ส่งสเปกละเอียด → ดู `SPECIAL_ROLES.md` (แยก "ประเภท" กับ "ฝ่ายชนะ"; บทพิเศษส่วนใหญ่ชนะพร้อมหมู่บ้าน; ผู้ลอกเลียนแบบชนะตามบทที่ลอก; มนุษย์ป่า=ชาวบ้านจนต้นแบบตาย แล้วเป็นหมาป่า)

### 🟢 Q22 — ลำดับตื่นกลางคืนมี 2 ฉบับในเอกสารเดียว
ข้อ 5 (17 ลำดับ: คู่รัก → เปลี่ยนบท → ... → หมอ → ผู้คุ้มกัน → **แม่มด** → ผู้หยุดความสามารถ) กับข้อ 21 (หมาป่า → ตรวจสอบ → ป้องกัน → **หยุดความสามารถ** → ประมวลผล) ต่างกัน: **ผู้หยุดความสามารถอยู่ท้ายหรือก่อน?** ถ้าอยู่ท้ายสุด จะหยุดอะไรไม่ได้เลยเพราะทุกคนทำไปแล้ว
- **ข้อเสนอ:** ให้ผู้หยุดความสามารถ (ทั้ง 2 บท) ทำงาน **ก่อนทุกบท** (ข้อ 21 แสดงเจตนาตามนี้) และให้ผู้สลับชะตาทำก่อนขั้นประมวลผล · ข้อ 12–14 ในเอกสารเจ้าของเว็บหายไป (เลขข้อกระโดดจาก 11 ไป 15) — มีเนื้อหาที่ตกหล่นไหม?

### 🟢 Q23 — ผู้ลอกเลียนแบบ/ผู้สลับชะตา กับความลับ (ผลต่อสถาปัตยกรรม)

### 🟢 Q25 — "หมาป่าแทรกแซงโหวต" (ผู้ใช้ขอเพิ่ม 2026-10-02)
- **คำตอบผู้ใช้:** "ปิดแค่การมองเห็นโหวต ไม่เห็นว่า A โหวต B · ที่ขึ้นแบบเรียลไทม์ดีอยู่แล้ว แต่ให้ขึ้นด้วยว่า A โหวต B ตรงชื่อ A"
- **ที่ทำ:** (1) บทใหม่ **หมาป่าผู้บดบัง** (ฝ่ายหมาป่า ร่วมกัดกับฝูง · ใช้ได้ 1 ครั้งต่อเกม ติ๊ก "บดบังโหวตวันถัดไป" ตอนส่งคำสั่งกัด) → โหวตครั้งถัดไปทุกคนมองไม่เห็นว่าใครโหวตใคร (เห็นแค่ใครโหวตแล้ว) · ขึ้นประกาศ "🐺 โหวตนี้ถูกหมาป่าแทรกแซง" (ไม่บอกว่าใครทำ) · คะแนนยังนับตามปกติ · ผลโหวตสาธารณะมีแต่คะแนนรวม (2) ตอนโหวตปกติ ตรงชื่อผู้โหวตขึ้น "→ ชื่อที่โหวต" ทันที
- **ข้อสมมติ 🔸A22:** การบดบังมีผลกับ "โหวตครั้งถัดไปที่เกิดขึ้นจริง" (ถ้าวันนั้นไม่มีใครถูกเสนอชื่อ การบดบังเลื่อนไปโหวตถัดไป) · ไม่บดบังการเสนอชื่อ · บทนี้เป็นบทเพิ่มนอก 50 บท (คะแนนสมดุล −7)

### 🟢 Q26 — คำสั่งปรับเกมจากผู้ใช้ (2026-10-02)
1. **อวตาร/ร้านค้า/เหรียญ:** ผู้ใช้ส่งภาพเกมแววูฟตัวอย่าง ขอให้ "ใช้โค้ดวาดอาร์ท มีของแต่งตัวเยอะๆ ซื้อได้ด้วยเงินในเกม" → ทำแล้ว (ดู PLAN M4) · **ข้อสมมติ 🔸A23:** ราคา/เหรียญเริ่มต้น 100 (ผู้ใช้สั่งลดจาก 200)/รางวัล 20+30+10 ตั้งขึ้นเอง ปรับได้ที่ `shared/avatar.ts` · กระเป๋าผูกกับอุปกรณ์ (ไม่มีล็อกอิน) ล้างข้อมูลเบราว์เซอร์ = เสียกระเป๋า (ยังไม่มีระบบกู้คืน)
2. **พื้นหลังตามช่วงเวลา / แชทธีมมืด** → ทำแล้ว
3. **เลือกโหวต/เสนอชื่อบนตารางผู้เล่น ไม่มีแผงโหวตแยก** → ทำแล้ว
4. **แตะไอคอนบทของคนตาย = ดูข้อมูลบท · ปุ่มซ้ายบน = ดูตั้งค่าห้อง + บทในเกมนี้** → ทำแล้ว
5. **ตายกลางคืนไม่เปิดบท / ตายจากโหวตเปิดบท** → ทำแล้ว (ตัวเลือก `revealOnDeath`: vote เป็นค่าเริ่มต้น) · **ข้อสังเกต:** ประกาศ "นายพรานยิง" เป็นเหตุการณ์สาธารณะ จึงเผยว่าคนนั้นเป็นนายพรานแม้ตายกลางคืน (ถ้าอยากซ่อน บอกได้)
